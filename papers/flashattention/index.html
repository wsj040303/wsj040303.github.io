本文精读 Dao 等人的 FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness（arXiv v2，2022），重点解释注意力矩阵为何造成显存读写、分块后如何保持 Softmax 的完整归一化、反向传播为何重算，以及论文的复杂度与实验分别支持什么结论。读者只需了解矩阵乘法和 Transformer 中 token 的基本含义。文中图表与数字均来自论文原文，没有重新运行 GPU 基准测试。

主要工作

FlashAttention 是一种 IO 感知的精确注意力算法：它仍计算给定掩码及缩放规则下的 softmax⁡(QKT)V\operatorname{softmax}(QK^{\mathsf T})Vsoftmax(QKT)V，但把查询、键和值分块，在 GPU 片上存储中生成并消费局部注意力分数，不把完整的 N×NN\times NN×N 分数矩阵与概率矩阵写入高带宽显存（HBM）。片上存储容量小，无法容纳所有键时，算法以每行的最大值、指数和及部分输出为状态，逐块完成同一个 Softmax。训练时再根据输入和这些状态重算局部概率，避免为反向传播保存二次方大小的矩阵。论文，§1、§3.1、算法 1、附录 B

论文给出前向算法的片外访问量 Θ(N2d2/M)\Theta (N^{2}d^{2}/M)Θ(N2d2/M)：NNN 是序列长度，ddd 是单头维度，MMM 是以元素数计的片上存储容量；作为对照，文中的标准实现需要 Θ(Nd+N2)\Theta (Nd+N^{2})Θ(Nd+N2) 次访问。这改变的是数据搬运量与中间结果占用，稠密精确注意力的主要矩阵乘法仍要处理 N2N^{2}N2 对查询和键。论文在特定 A100、模型及基线条件下报告 BERT-large 端到端训练时间由 20.0 分钟降到 17.4 分钟，GPT-2 medium 由 Hugging Face 基线的 21.0 天降到 6.9 天。两个结果属于不同实验，不是一个通用加速系数。论文，定理 1–2、表 1–2

GPU 的高带宽显存（HBM）容量大，片上静态随机存取存储器（SRAM，包括共享内存等用于局部计算的片上资源）容量小、带宽高。论文以 A100 为例：HBM 容量为 40–80 GB，带宽约 1.5–2.0 TB/s；每个流多处理器有 192 KB 片上 SRAM，片上带宽估计约 19 TB/s。这里的 IO 指 HBM 与片上存储之间的数据读写。判断运算是否受显存带宽限制，还要看算术强度：每读写一个字节所完成的运算量。如果搬运数据期间不足以让计算单元持续工作，运行时间就主要由数据搬运决定。论文，§2.1、图 1

标准注意力中的两次矩阵乘法可以具有较高的算术强度；夹在两次乘法之间的 Softmax 则要读取 N×NN\times NN×N 的分数矩阵 SSS，对每行求指数、归约并归一化，再写出同样大小的概率矩阵 PPP。这类逐元素和归约操作对每次数据读写所做的计算较少，因此更容易受 HBM 带宽限制。论文以 GPT-2 的 N=1024N=1024N=1024、d=64d=64d=64 为例：SSS 或 PPP 各有 1,048,576 个元素，而单个 QQQ 矩阵有 65,536 个元素。标准实现需要让这两张较大的中间矩阵在各阶段进出 HBM。因此，论文将注意力中的部分或多数操作归为内存受限；两次矩阵乘法仍可能受算力限制。论文图 2 中计算量增加、HBM 读写减少而运行时间下降的对照，也支持这一分析。论文，§2.1–2.2、图 2

问题定义

论文的标准实现先算 S=QKTS=QK^{\mathsf T}S=QKT 并把 SSS 写入 HBM，接着读 SSS 求 P=softmax⁡(S)P=\operatorname{softmax}(S)P=softmax(S) 并写回 PPP，最后再读 PPP 与 VVV 求 O=PVO=PVO=PV。SSS、PPP 都有 N2N^{2}N2 个元素；训练反向传播还要使用中间概率。因而这个实现除输入和输出外，需要随序列长度平方增长的中间存储和显存访问。多头和批量处理会把这些成本乘上相应的头数与批量数。论文，§2.2、算法 0

FlashAttention 要同时满足两项约束：前向不能预先看到一整行 SSS，却要得到对整行归一化后的精确输出；反向不能保存整张 PPP，却要能计算 Q,  K,  VQ,\;K,\;VQ,K,V 的梯度。精确在此指算法不因跳过注意力位置而改变所定义的稠密注意力运算；有限精度计算、归约次序与具体内核仍可能造成数值差异。论文另设的块稀疏扩展会跳过指定块，计算的是由稀疏掩码定义的注意力，不能与稠密精确版本的语义混同。论文，§3.1、§3.3、附录 B

反向重算与存储代价

标准反向传播使用正向得到的 PPP 求梯度；若保存整张 PPP，二次方存储又会回来。FlashAttention 前向保留 Q,  K,  VQ,\;K,\;VQ,K,V、输出 OOO 以及每行 m,  ℓm,\;\ellm,ℓ。反向处理一对查询与键/值块时，重新计算该块分数和 Pij=exp⁡(Sij−mi)/ℓiP_{ij}=\exp(S_{ij}-m_{i})/\ell_{i}Pij​=exp(Sij​−mi​)/ℓi​，再结合输出梯度 dOidO_{i}dOi​ 求局部的 dQi,  dKj,  dVjdQ_{i},\;dK_{j},\;dV_{j}dQi​,dKj​,dVj​，从始至终只让局部 Br×BcB_{r}\times B_{c}Br​×Bc​ 概率块待在片上。使用 Dropout 时，还要根据正向的随机状态重现该块掩码。论文，§3.1、附录 B.2–B.4、算法 4

IO 复杂度与适用条件

以论文算法 1 的循环计算，K,  VK,\;VK,V 各块在外循环装入；约有 Tc≈N/Bc≈Nd/MT_{c}\approx N/B_{c}\approx Nd/MTc​≈N/Bc​≈Nd/M 个键/值块。对每个外循环，QQQ、部分输出和行统计量合计需要 Θ(Nd)\Theta (Nd)Θ(Nd) 量级的 HBM 访问，于是主项为式 (3)：

Θ(Tc⋅Nd)=Θ ⁣(N2d2M)(3)\Theta(T_c\cdot Nd)=\Theta\!\left(\frac{N^2d^2}{M}\right) \tag{3}Θ(Tc​⋅Nd)=Θ(MN2d2​)(3)

这里数的是元素访问次数，不是字节；换算为字节还需考虑数据类型，不能直接把 MMM 代成以 KB 计的 SRAM 容量。论文定理 2 的形式适用于 d≤M≤Ndd\le M\le Ndd≤M≤Nd 的模型区间；当 MMM 足以容纳更大块时，重复扫描次数随之减少。论文，§3.2、定理 2

定理 1 给出的额外存储为 O(N)O(N)O(N)，指在输入 Q,  K,  VQ,\;K,\;VQ,K,V 和输出 OOO 之外的行最大值、行和等状态；输入输出自身仍有 O(Nd)O(Nd)O(Nd) 个元素。反向的梯度张量也各占 O(Nd)O(Nd)O(Nd)。因此，对固定头维度 ddd，注意力相关的中间存储随 NNN 线性增长，而不是整个 Transformer 的所有显存占用都成为 O(N)O(N)O(N)。论文，定理 1、附录 B.4

论文命题 3 的下界有明确量词：不存在一种算法在该区间的所有 MMM 上都达到 o(N2d2/M)o(N^{2}d^{2}/M)o(N2d2/M) 次片外访问。证明取 M=Θ(Nd)M=\Theta (Nd)M=Θ(Nd) 时至少必须读入或写出 Ω(Nd)\Omega (Nd)Ω(Nd) 个元素。这一论证不能单独推出“对每一个固定的 MMM，FlashAttention 都达到逐点最优下界”；论文也把更细的参数化下界列为后续工作。此区分影响对“IO 最优”的理解。论文，§3.2、命题 3

实验与证据

片外读写与注意力耗时

图 2 左表的条件是 A100 上的 GPT-2 medium 注意力，序列长度 1024、头维度 64、16 个头、批量 64，计入前向与反向。标准实现与 FlashAttention 分别为 66.6 与 75.2 GFLOPs、40.3 与 4.4 GB HBM 读写、41.7 与 7.3 ms。同一设置下，FlashAttention 计算量增加约 13%，HBM 读写量却约为原来的九分之一，耗时约为原来的六分之一；该对照支持论文提出的 IO 瓶颈解释，但不意味着任何设备与长度上都必然更快。图中间随块大小增大，HBM 访问和耗时先下降；当片上容量、计算或其他成本成为限制时，继续增大块不能无限加速。论文，§3.2、图 2

图 3 左侧的黑色点线是稠密 FlashAttention，蓝色和橙色分别是 PyTorch 与 Megatron 注意力；绿色虚线为块稀疏扩展。短序列时，黑线在几条近似或稀疏方法的曲线之下，尽管稠密方法的渐近计算量更高；约在 512–1024 token 的区间，一些近似曲线开始与它交叉。右侧黑色点线随长度近似线性增长，而若干需要二次方中间矩阵的实现更早耗尽这次测试的 40 GB A100 显存。图示只覆盖这里的实现、设备与批量条件，也只量“注意力相关内存”，不能据此推断完整训练的总显存曲线。论文，§4.3、图 3

结论

FlashAttention 把注意力的性能问题从“只减少算术运算”扩展为“同时安排片上计算与 HBM 读写”：分块只临时生成局部分数，在线 Softmax 用最大值、指数和与部分输出维持整行归一化，反向重算局部概率而不保存整张矩阵。论文的定理给出所述内存模型下的访问量，A100 实验展示计算量可略增而注意力耗时下降；端到端训练和长上下文任务结果则说明这种算子优化在特定模型与负载中能转化为实际收益。评估其他场景时，仍需分别核对序列长度、头维度、片上容量、掩码、数值精度和对照实现。
