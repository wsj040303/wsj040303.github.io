阅读对象：DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning，以本地 PDF 的 arXiv v2（2026 年 1 月 4 日）为准。本文从论文和随附的 comments.md 中的提问重新组织论证；论文陈述、我的解释及尚未披露的实现细节会明确区分。文中的“R1”指 DeepSeek-R1，“Zero”指 DeepSeek-R1-Zero。

如果只记住一条主线，就是：预训练后的 DeepSeek-V3-Base 已能生成一些可行的解题路径；可验证题目提供可靠的最终结果奖励；GRPO 在同一道题的多个回答中放大相对更好的路径。 Zero 用这个组合证明了不用先给人工推理轨迹也能显著提高推理成绩，却留下语言混用和可读性问题；R1 再用冷启动、两轮强化学习及中间的监督微调补齐使用体验。这里的“纯 RL”只表示 Zero 的后训练跳过了先行 SFT，绝不是没有预训练、没有题目或没有奖励。

1. 先认清三种训练信号

预训练、SFT 与 RL 各在做什么

预训练通常让模型在大量文本上预测下一个 token。这个目标不等于“只学会接词”：数学解法、代码、解释和语言知识都藏在文本分布里；足够大的基座模型可以生成包含正确思路的候选。论文附录 A.1 特别说明，V3-Base 预训练见过大量数学和代码内容。后训练改变的是哪些行为更常被实际采样出来，也可能显著改变任务正确率，不能简单说成“预训练学知识，后训练只学礼貌”。

SFT（监督微调）给定问题与示范回答，让模型拟合示范文本。RL（强化学习）则让模型自己输出，再根据奖励调整生成概率：它只需知道某个结果好不好，不一定需要事先写好每一步推理。两者都属于预训练之后的阶段；GRPO 是本文实施 RL 的优化算法，不是与 SFT 并列的一种训练阶段。通常的后训练先 SFT 再 RL；Zero 从 V3-Base 直接开始 RL，R1 则重新引入 SFT。见论文引言、§2、§3 与附录 A.2。

论文批评人工标注轨迹可能带来“认知偏差”，但没有给这个词下可测量的心理学定义，也没有实验量化偏差。结合附录 A.2，较稳妥的理解是：人工示范可能省略反思、验证和试错，把标注者习惯当成唯一目标，压缩模型探索其他路径的空间。这是作者提出 Zero 的研究动机，不是已经证明“人类推理总比模型差”。R1 最后依然使用人工参与整理的数据，说明作者也承认示范数据对可读性和通用能力有价值。

论文里的 STEM 指什么

日常的 STEM 是 science、technology、engineering、mathematics（科学、技术、工程、数学）的合称。论文附录 B.3 的 STEM 训练类别却是约 22K 道理科选择题，主要覆盖物理、化学、生物；数学、代码和逻辑被另列为类别。把“STEM 22K”读成“所有理工科训练题只有 22K”会误解数据表。论文在讨论 GPQA 等评测时使用的“STEM fields”又是宽泛的学科说法。

3. 把 GRPO 三个式子拆开

式 (3)：组内优势从哪里来

先为同一题的 GGG 条回答算出奖励 r1,…,rGr_1,\ldots,r_Gr1​,…,rG​，然后做组内标准化：

Ai=ri−rˉsr,rˉ=mean⁡(r1,…,rG),sr=std⁡(r1,…,rG).(3)A_i=\frac{r_i-\bar r}{s_r},\qquad \bar r=\operatorname{mean}(r_1,\ldots,r_G),\quad s_r=\operatorname{std}(r_1,\ldots,r_G). \tag{3}Ai​=sr​ri​−rˉ​,rˉ=mean(r1​,…,rG​),sr​=std(r1​,…,rG​).(3)

若一组答案全对或全错，sr=0s_r=0sr​=0，论文所写的式 (3) 在数学上无定义。实际代码必须通过加小常数、屏蔽或其他方式处理；论文这一式没有交代处理细节。无论采用哪一种数值处理，同组没有奖劣之分时就缺少这种相对学习信号。因而作者强调难题、可靠验证器与足够 RL 算力的组合，而不是一味增加简单题。

PPO 留下的裁剪，与 GRPO 省掉的价值模型

PPO 原论文的关键思想是：新策略不能凭一批旧样本把某个动作的概率推得过远。语言模型版 PPO 常用价值模型（critic）估计从某个生成前缀出发的未来回报，再计算优势；在结果奖励只出现在回答末尾、且模型会中途推翻自己的长思维链里，前缀预估最终成绩尤其困难。价值模型本身也占显存和算力。GRPO 保留 PPO 风格的裁剪目标，改用式 (3) 的组内奖励估优势，于是不必训练这个 critic。附录 A.3 的对照只支持“在作者设置的 MATH 训练中更省资源、少调一个 GAE 参数”；PPO 的 λ\lambdaλ 调到 1.0 后可接近 GRPO，并不能据此断言 GRPO 在所有任务上都更准。

4. 奖励仍在：不用神经奖励模型的准确边界

comments.md 中最关键的一次追问是：“强化学习不就是靠奖励更新参数吗，没了奖励还如何训练？”这里被拿掉的只有推理任务的神经奖励模型，不是奖励本身。Zero 的规则奖励分为正确性与格式两项，论文式 (4) 写作 Rrule=Racc+RformatR_{\mathrm{rule}}=R_{\mathrm{acc}}+R_{\mathrm{format}}Rrule​=Racc​+Rformat​，两项等权。数学题让最终答案进入可解析格式再对照标准答案；编程题通过预设测试；格式项检查思考与答案标签。GRPO 只规定“怎样利用这些分数更新策略”，规则奖励是另一项设计选择，并非 GRPO 算法的定义。

为何偏向规则？神经奖励模型会把复杂回答压成近似分数。策略长时间优化时，可能找到“让打分器喜欢但实际没解决问题”的捷径，即奖励攻击；重训奖励模型也增加成本。可验证的数学、代码、选择题给出了较硬的检查器，适合长时间 RL。论文附录 B.3 的训练类别包括数学约 26K、STEM 约 22K、逻辑约 15K，表 4 另列代码 17K；正文还描述了约 8K 修 bug 题。这些数字是题目量，不是生成回答量，也不能与 66K 通用偏好对简单相加解释为一次训练批次。

问题是，写作、开放问答、有用性和安全性没有同样直接的程序真值。R1 的第二轮 RL 对这些通用任务使用神经奖励模型，最后 400 步才引入通用指令数据和偏好奖励；推理任务仍沿用规则奖励。论文 §3.2.2 用 Rreasoning+Rgeneral+RlanguageR_{\mathrm{reasoning}}+R_{\mathrm{general}}+R_{\mathrm{language}}Rreasoning​+Rgeneral​+Rlanguage​ 表示混合批次的奖励来源。这里是按题目类型选择适用分量，不能理解为每道数学题都同时得到通用偏好模型的打分。

论文附录 B.5 给了奖励攻击的直接现象：有用性奖励模型的分数持续上升时，Codeforces 测试通过表现却下降。因而“规则更可靠”也有边界：它依赖答案解析正确、测试用例覆盖足够、题目无泄漏；仅有最终答案奖励不会自动保证中间每一步真实无误。

5. 从 Zero 到 R1：为什么后来又把 SFT 请回来

下面把论文图 2 的模型谱系展开。起点都在 V3-Base；“Dev”是中间检查点，不是另外三条独立路线。

模型/阶段 输入与主要做法 要解决的问题
R1-Zero V3-Base → 推理题规则奖励 RL 验证无需先标注推理轨迹也能诱导长链推理
R1-Dev1 V3-Base → 数千条冷启动长 CoT 的 SFT 先建立较易读、语言更一致的起点
R1-Dev2 Dev1 → 第一轮推理 RL，加入语言一致性奖励 继续提升可验证推理，控制混语
R1-Dev3 Dev2 → 拒绝采样构建数据，再做约 800K 条 SFT 补推理样本，也补写作等通用任务
R1 Dev3 → 第二轮混合 RL；最后 400 步引入通用偏好奖励 把推理与有用性、安全性一起调到可用状态

冷启动不是“让人工写完所有思维链”。论文附录 B.3.2 描述：先对数千道题让 Zero 多次采样，筛出正确且可读的结果；数学用 SymPy 比较表达式，另以规则过滤重复和语言混合，再由 V3 润色，人工改写样例并复核模型改写结果。这里有人参与，所以最终 R1 不能被描述为“全程无人类数据”。第二轮 SFT 约 600K 推理样本与约 200K 非推理样本，具体统计是 804,745 条（附录 B.3.3、表 5）。拒绝采样意指生成多个候选后筛掉不合格结果，用保留的轨迹做监督数据。

实验表 3 也解释了为何要多阶段：Zero 的 AIME 2024 pass@1 为 77.9，冷启动后 Dev1 降至 59.0，但 IF-Eval 从 46.6 升到 71.7；后续 RL 逐步追回推理分，最终 R1 达 79.8，IF-Eval 达 83.3。数字展示了不同目标在阶段间的取舍，不能把“加一轮 SFT”理解为所有指标都会单调增加。第一轮 RL 的长度上限是 32,768 token、温度 1；第二轮 RL 温度改为 0.7，总计 1,700 步，其中通用偏好奖励仅最后 400 步使用（§3.2）。

6. 语言混用：输出语种、词表与工具要分开看

模型如何“决定”用中文还是英文

论文明确观察到 Zero 会在一条思维链中混中英，认为 V3-Base 以中英为主的训练语料可能是原因；它没有给出某个 token 上的语种选择实验。就一般自回归生成机制而言，模型每一步在同一套 token 候选上预测概率，提问语言、提示词、已经生成的前缀、领域文本都会改变分布。R1-Zero 的英文模板可能影响语言起手，但这是根据模板的推测，论文未做因果消融。V3 是 MoE 模型，“共享一套分词器和同一模型”也不等于每个 token 都经过完全相同的专家参数；本文不能由混语现象反推出内部专家按语言分工。

R1 的工程补救有三层：冷启动时筛除或翻译混语思考；第一轮 RL 在结果奖励上加语言一致性分数 Rlanguage=Num(Wordstarget)/Num(Words)R_{\mathrm{language}}=\mathrm{Num}(\mathrm{Words}_{\mathrm{target}})/\mathrm{Num}(\mathrm{Words})Rlanguage​=Num(Wordstarget​)/Num(Words)；第二轮继续在推理与非推理数据上使用。附录 B.6 在 R1-Distill-Qwen-7B 上做消融：加奖励后语言一致性保持稳定，数学表现接近，代码略降。因此“语言更一致可能付出一点任务表现代价”有这项实验支撑，但不要把 7B 消融直接写成原版 R1 的精确损失。

词表大小 VVV 与同一段文本的 token 数 NNN

comments.md 有一处很好的纠错：先前回答把“词表大”直接写成“同一文本 token 数少，训练就快”。这两个量必须分开。VVV 是 token ID 的种类数，直接影响嵌入表、输出层类别和相应计算；NNN 是某段文本被当前分词器编码出的序列长度，直接影响上下文占用及与序列长度相关的计算。对某种语言学到了更合适的合并，NNN 才可能下降；单独增大 VVV 不保证那种语言分得更细还是更粗，净训练成本也取决于两种效应。支持的语言越多，困难还来自不同语言的训练语料量与质量，不只是词表容量。

DeepSeek-V3 的技术报告写明使用 128K byte-level BPE；这条分词器资料来自 V3 技术报告，不是 R1 论文自己的实验。byte-level 编码可以用更碎的 token 表示罕见字符，因此“模型能打出中文”不能反推“词表里一定有每个中文字的独立 token”，更不能反推中文任务质量。对于非常低资源的语言，常见可能是切分成本高、理解和输出质量下降、语言漂移或表达能力不足；具体会不会承认“不擅长”，还取决于模型的对话训练和指令。只测 NNN 能判断编码代价，不能单凭 NNN 判定语言能力。

如果模型被放进一个有翻译工具、调用接口与相应策略的 agent，系统可以先翻译输入、再翻译输出，或在中间用高资源语言处理；这取决于系统提供的工具与调用规则，并非基础 LLM 自发拥有的能力。论文 §6 明确把工具使用列为当时 R1 的限制，搜索、计算器等不能直接用于增强输出；因此不能把“agent 可以调用翻译器”写成论文中 R1 已经做过的事。

7. 谁给通用回答判好坏？论文交代了什么

comments.md 最后两问看似矛盾：“不是说不用奖励模型吗？”“两个候选谁来评？”答案是任务分流。推理题用规则；通用题使用有用性和安全性奖励模型。论文 §3.1 描述有用性数据为 66K 个偏好对：每对是一条用户问题和 A/B 两个候选回答；用 DeepSeek-V3 按附录 B.2 的裁判提示判断，四次独立查询中随机互换 A/B 位置，平均判断后只保留差异足够明显的对；还使选中与落选回答的整体长度相近，以抑制长度偏差。附录的裁判提示要求模型先给出自己的答案、对比两份回答并输出五档胜负标签。

这里要保留几个资料边界。原文将“通过提示 V3 生成偏好对”和“四次向 V3 查询以评判”写得很紧，能确认 V3 参与偏好判定；却没有说明两条候选回答的具体采样温度、top-p 或生成次数，所以不能说它们“一定因为 temperature 不同”。四次查询是评判而非“四次新候选生成”。论文还未清楚公开五档标签如何数值化并计算筛选阈值 Δ>1\Delta>1Δ>1；复现这一过程需要额外约定。安全奖励模型另用 106K 条带“安全/不安全”标签的响应训练，采用单条样本判别；论文没有在此明确交代每个安全标签由谁标注。

候选与裁判同属 V3 流程意味着有自我偏好等潜在偏差，这是对方法的风险分析，不是论文已经测出的偏差大小。规则奖励也并非在所有场景都绝对客观：数学表达式判等与程序测试的覆盖度都会影响所谓的“正确”。

8. “等等，我发现了”是证据，还是修辞？

论文表 2 的中间版 Zero 会在解题中写“Wait, wait. Wait. That’s an aha moment…”，随后回头检查。作者把它称为带拟人语气的重新思考；图 9 同时报告反思相关词汇在训练中更常出现。可观察事实是文本中出现了回溯、相关词频与成绩随训练变化。更强的命题——模型真的产生人类式顿悟、说出 wait 本身导致正确率提升——没有被这组观察证明；它也可能是相关语料风格与获得奖励的有效纠错模式共同被放大。读者觉得句子重复、突兀，是合理的阅读感受，不能拿“啊哈”这个词代替对解题步骤的核验。

论文附录 B.3.2 甚至专门提醒：拟人化思考可能让用户产生不应有的信任，生动推理模式主要反映工程化启发式，不意味着模型已经获得类似人的智能。因此判断长思维链应看可验证结果、错误修正是否真实发生，而不看它是否写了“我意识到”。

9. 实验能支持多强的结论

Zero 的 AIME 2024 pass@1 在纯 RL 过程中从 15.6% 增至 77.9%，自一致性解码的 16 次采样结果达 86.7%；平均回答长度也随训练增加（图 1）。这支持“在强预训练基座和可靠可验证任务上，结果奖励足以诱导更长的搜索与反思行为”。R1 表 3 的最终 AIME pass@1 为 79.8、MATH-500 为 97.3、Codeforces rating 为 2029；不同任务的计算口径不能混成一个“总体推理准确率”。

外推时至少守住四个边界：第一，研究以大规模 V3-Base 为起点，小模型未必能仅靠同样 RL 涌现；第二，最终答案对了不保证每一步推理忠实，尤其不保证拟人化措辞有认知含义；第三，没有可靠验证器的写作等任务仍依赖 SFT 与偏好模型，长时间纯 RL 会遇到奖励攻击；第四，论文自己列出工具使用、结构化输出、多语言和过度思考的限制（§6）。这篇工作的贡献不是“奖励取代一切教学”，而是把“结果可验证时能从已有候选中筛出更好的推理路径”做成了可运行的大规模训练路线。
